## 正式 C/MySQL 接入仍需修的五处

1. `app/core/providers.py:get_job_store` 与 Worker `main` 仍实例化 `SqliteJobStore`。正式知识任务改为同一个 C store；来源/原件/文档先按 C 登记。上传现在生成新UUID、document_version=v1，这是桥身份，尚不是C登记身份；不要把桥库任务当正式C任务。
2. `app/worker.py:_run_knowledge_index` 当前先写文件再激活，落盘顺序已正确；但 activate 的 with 已退出才调用 complete_job，之后 run_once 又调用一次 complete_job。正式实现须在同一个 C write 内激活并完成，外层不得重复完成。桥库 `write()` 本身也没有共享同一连接，各方法各自提交，不能只移动缩进就认定原子性。
3. 隔离故障实证：完成阶段抛异常后 index仍ready、job为failed；桥库随后接受旧租约把该任务改成succeeded。切换 C 的 JobLease/current attempt 验证，分别验证 activate失败、complete失败、旧租约拒绝及新租约重传去重；不使用桥库行为关闭这些验收。
4. 当前 parser_version=`e-knowledge-0.5.0`、embedding_model_version=`e-keyword-index` 是D硬编码，与E产物不符。直接使用 prepared 返回的 `text-parser-0.5.0` / `keyword-tfidf-0.5.0`；传入明确的原文 document_version 和新索引 version，持久化用 C 原生 persist_file，激活附 byte_size 和 lease。
5. 配置正式 `knowledge_snapshot_loader`，移除互斥的 knowledge_index_path。`e_bridge.answer_message` 目前仍在调用E之前检查旧快照文件是否存在；启用C引用加载后应按选定加载方式判断可用性，不能因没有旧快照文件而短路返回“知识库未建立”。桥重建快照还重造了chunk_id，正式问答请保留E/C已提交的真实locator。

推荐事务顺序如下；长计算和持久化在事务外，D自己在独立短事务续租。

```python
with store.write() as uow:
    claimed = uow.jobs.claim_job(worker_id, now, job_type="knowledge_index", job_id=job_id)
lease = JobLease(**claimed["lease"])
prepared = dispatch_analysis_job("knowledge_index", {
    "document_id": doc["id"], "document_version": doc["document_version"],
    "version": index_version, "file_path": trusted_path, "metadata": doc,
})
staged = store.persist_file(source_id=doc["source_id"], original_name="index.json",
                            stream=io.BytesIO(prepared["artifact_bytes"]))
with store.write() as uow:
    index = uow.knowledge.begin_index(document_id=doc["id"], version=index_version,
        job_id=lease.job_id, parser_version=prepared["parser_version"],
        embedding_model_version=prepared["embedding_model_version"], lease=lease)
for offset in range(0, len(prepared["chunks"]), 1000):
    with store.write() as uow:
        uow.knowledge.write_chunks(index["id"], prepared["chunks"][offset:offset + 1000], lease)
with store.write() as uow:
    uow.knowledge.activate_index(document_id=doc["id"], version=index_version,
        artifact_path=staged["relative_path"], artifact_sha256=staged["sha256"],
        expected_artifact_byte_size=staged["byte_size"],
        expected_chunk_count=prepared["chunk_count"], lease=lease)
    uow.jobs.complete_job(lease, {"index_id": index["id"]}, completed_at)
```

该片段使用实际 C/E 签名；D应补自己配置、授权、续租和异常处理，异常传播触发整体回滚。加载签名与实际JSON文件见 [E正式回执](E051正式交付与CD回执.md)。
