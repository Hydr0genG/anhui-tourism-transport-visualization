## 2. D §七五项确认

| 项目 | E 答复 |
|---|---|
| confidence_threshold | 接受 D 的 27 号 HTTP 响应顶层回读固定 0.5、26 请求不接受自定义阈值。E 的原生 `VideoAnalysisConfig` 仍包含 `confidence_threshold=0.5`，位于 `CountsResponse.analysis` 内；D 映射公共响应时不得把顶层扩展字段传给 E 的严格模型。 |
| weights_sha256 / model_source_revision | 接受由 D 自有 provenance 持久化，并在 D HTTP 响应层添加。E `CountsResponse` 不接收这两个额外顶层键。应从实际加载的 `counter.provenance` 取值，并绑定到本次 analysis，不用当前模型的审计值补写旧分析。 |
| manual_validation | 当前 E 契约为 `{sample_count, mae}`，没有新增必填字段；尚无人工评估时必须为 `null`，不能用 `{sample_count:0, mae:0}` 表示未评估。密集/稀疏分组、标注人员、ROI、权重和样本清单放独立误差报告，不能硬塞进严格结果模型。 |
| document_version | E 有严格依赖：产物中的原文版本必须等于 C `get_document(document_id)` 返回的 `document_version`。由登记原文的一侧按 C 约定生成并登记，D 读取后透传给 E，不另造 `v1`。本批 C 固定资料采用 `sha256:<完整摘要>`；必须读取每份文档自己的值，不能复用某一份的摘要。修改版本后应重新生成绑定正确版本的索引产物，不能只修改数据库中的版本字符串。 |
| index_version | `e051-index-1` 是 E 验收样例名称，不是强制格式。D 的 `v{n}` 可以保留；同一文档的重建版本应唯一，产物 `index_version`、C 索引版本和读取引用必须一致。`document_version` 与 `index_version` 分开传递。 |

## 3. D §六六项答复

1. **人工 MAE**：待人工真值。本轮不再做算法对照，已有抽帧可用于 P2PNet 单模型验收。CPU 三帧 31/41/31 仅证明推理链路，不证明准确率；没有真值前 `manual_validation=null`。密集/稀疏分组 MAE 需有相应标注样本后分别报告。
2. **GPU / OpenVINO**：本轮不开放。D 保持 `pytorch` / `CPU`，其他配置明确拒绝。原始队长实现存在按 CUDA 可用性选择 anchor 设备的行为，现有 E 适配器会拒绝 CUDA 可用的主机；不能在 GPU 主机上直接宣布 CPU 配置已验收。
3. **语义绑定失败**：已有可运行入口，见 §4。摘要正确也不能绕过 E 对原文版本、索引版本、片段正文和 locator 的一致性校验；失败抛 `DependencyUnavailable`，不回退旧内存答案。
4. **旧租约拒绝**：已有真实 C store 隔离复现，见 §5；D/MySQL 双端注入仍需在 D 的隔离库按同样步骤执行并回传，不能用 E 的 SQLite 结果关闭 D/MySQL 验收。
5. **knowledge_reindex 展开职责**：确认由 D Worker 展开。E `reindex_documents()` 只提交 `{document_ids, reason}` 信封，不附逐文档子任务描述。D 解析每份文档的 C 身份、原文版本和可用输入源后生成 `knowledge_index` 子任务；不可用项需显式记录 skipped/失败原因，父任务不能把所有请求项表述为均已重建。
6. **重建输入源**：本轮接受 D 使用仍可验证的 staging 原文件；输入必须对应 C 登记的文档及原文版本，不能拿过期 staging 字节按新版本重新索引。E 只接收已授权、已校验的本地 `file_path` 和元数据，不提供 C 原始 asset 下载接口。现有 `get_index_artifact_ref` 返回的是索引产物，不能当作原始文档。原始 asset 的取回入口、授权和完整性由 D/C 确认；staging 缺失时显式跳过，不虚构文件或重建成功。

## 5. 旧租约及事务注入

同一隔离接收命令覆盖两条路径，不需要伪造 JobLease，也不需要修改 C 的 JobAttempt 表：

- **过期恢复**：以过去时间登记并领取任务，保存 C 返回的旧 lease；调用 `recover_expired(now)`，再用旧 lease 调 `update_progress`，应抛 C `LeaseLost`；重领取得新 lease 后可完成。报告 `checks.expired_lease_rejected`、`checks.recovery_new_lease_completed` 为 `true`。
- **失败重试发布**：旧 lease 写好未激活索引后，调用 `fail_job`，以测试管理员 `retry_failed`，重领得到新 lease；旧 lease 调 `activate_index` 应抛 `LeaseLost`；新 lease 重写相同片段应去重，并能激活、完成。报告 `old_attempt_cannot_publish_after_retry`、`new_attempt_reuses_chunks_and_publishes` 为 `true`。
- **原子发布**：在 `activate_index` 后、完成任务前注入异常，或在同一事务内完成任务后再抛异常；读回应仍是旧活动版本，任务未完成。报告 `completion_failure_rolls_back_activation`、`activation_and_job_completion_rollback_together` 为 `true`。

D/MySQL 联调步骤：在独立测试库建立一份授权测试文档；用 D 当前 C store 适配器保留真实 lease，分别按上述恢复/重试路径操作，再经 D 的正式 `activate_and_complete` 尝试发布。保存异常类型、任务状态、attempt_no、活动索引版本及事务前后断言，确认旧 attempt 没有激活/完成、新 attempt 可正常完成；回执不公开 lease_token。E 的隔离脚本是可运行参考，未声称已经执行 D 的适配器或 HTTP。
