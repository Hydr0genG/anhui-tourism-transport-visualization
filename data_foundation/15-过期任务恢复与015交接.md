## 状态、历史及事务

只处理 running、当前尝试尚未结束且 lease_expires_at <= now 的任务。候选读取不加锁；逐个通过主键以 SKIP LOCKED 获取 Job，再锁当前 JobAttempt，刷新并重查状态和期限。被锁住的候选跳过，续约或已结束的候选不会被错误恢复。

| 情况 | Job 结果 | JobAttempt 结果 |
|---|---|---|
| attempt_count < max_attempts | queued，available_at=now；清空开始/结束、计数、结果引用和错误字段，保留累计次数及原任务内容 | 当前旧尝试标记 expired，记录 finished_at=now、error_summary=lease_expired，保留旧 token 和历史 |
| attempt_count >= max_attempts | failed，记录 finished_at=now、error_summary=lease_expired，停止自动排队 | 同样记录 expired，不创建新尝试 |

下一次领取才增加 attempt_count，并产生新 token；恢复不创建新的任务或执行尝试。重复调用不会重复增加次数、重复结束旧尝试或重复排队。调用方事务出错时任务和尝试修改同时回滚。

写路径 ensure_lease 统一按 Job → JobAttempt 加锁并刷新，校验当前尝试编号、token、运行状态、结束状态和期限。默认实时时钟在拿到锁后读取。锁持有到外层事务结束，心跳、任务结束和现有知识/视频租约写入使用同一保护。读路径保持非加锁检查，读到的租约快照不能替代写路径校验。

## D 的接入与边界

- 由 D 的唯一 Worker 决定何时调用和轮询间隔，C 本版不启动定时任务，也不新增退避算法。恢复后可立即领取，遇到零计数或锁竞争时沿用 D 的轮询/事务重试策略。
- 领取与恢复使用短事务；文档解析、模型推理等长操作在事务外进行。知识索引激活/分析完成与 jobs.complete_job 应在同一 store.write 内提交，例子沿用已有交接样例。
- lease 检查通过后，写事务保持 Job 锁，恢复不能同时重排该任务。本版按操作校验时刻和事务顺序验证；不承诺在提交瞬间再次验证实时时钟。
- 不删除已提交业务记录、不重置知识索引/视频分析状态、不修复业务重试幂等。处理函数能否恢复半成品需 D/E 另行验收，不能把 Job 重新排队视为算法恢复成功。
- 单批最多选取 batch_size 个候选，不补满被锁跳过的名额。既有队列索引和锁范围限制仍保留，不宣称高并发吞吐通过。
- 无需新增迁移。0.1.4 的类型/ID 领取筛选继续可用；G08 的 update_progress/retry_failed、G09 的完整业务归属及其他正确性缺口仍未全部关闭。

## 安装与复验

从完整交接 ZIP 的 data_foundation 目录执行：

```bash
python -m pip install release/anhui_data_foundation-0.1.5-py3-none-any.whl
PYTHONPATH=. python -m pytest
PYTHONPATH=. python examples/de_handoff_smoke.py --target local --part all --report /path/to/legacy-report.json
```

Windows PowerShell 先设置 `$env:PYTHONPATH="."`，再执行不带 PYTHONPATH 前缀的 Python 命令。wheel 不含外部迁移、样例和原件，需使用 ZIP 的配套目录；已有 0005 数据库不需要新增结构迁移。

配置 TEST_DATABASE_URL 指向 mysql+pymysql、名称以 `_test` 结尾且无表的独占测试库，再运行：

```bash
python examples/verify_job_recovery.py --report /path/to/mysql-recovery.json
```

脚本自行迁移，不清理旧库，不得对业务库执行。全部任务和文档均为合成测试资料；虚拟时间控制到期边界，不等待真实租约到期。
