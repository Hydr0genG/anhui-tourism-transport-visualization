## 架构一页说明

```text
                         C：data_foundation

  来源台账与原件 → 解析/标准化 → 质量核验 → 幂等与版本处理
       │                                      │
       ↓                                      ↓
   受管理文件目录                           MySQL
   原文/资料/录像                 事实/来源/版本/任务/结果
       ↑                                      ↑
       └──────── C 的受约束数据访问包 ─────────┘
                            ↑
               ┌────────────┴──────────────┐
               D                          E
      API / 登录 / 历史预测       RAG / 录像计数 / 短时预测
               ↓                    结果经 C 回写
          A/B 前端页面
```

E 的数值问答通过 D 注入的查询工具访问 C。C 不直接面向浏览器提供接口，也不运行另一套登录、预测模型或向量检索服务。

| 模块 | 你交付的内容 | 接收方 |
|---|---|---|
| 基础目录 | 实体、指标、来源、真实可用粒度 | D → A/B/E |
| 客流数据 | 原件、观测、修订、覆盖率、受约束查询 | D |
| 数据更新 | 来源适配、清洗、幂等导入、周检查、质量报告 | D worker |
| 身份存储 | 用户与会话读写，供 D 实现登录 | D |
| 假期与事件 | 日期定义、公告、影响对象与变更历史 | D → A/B |
| 知识资料 | 官方资料及元数据、片段和索引版本存储 | E/D |
| 录像材料 | 授权、片段、人工标注、分析配置和计数存储 | E/D |
| 预测与任务 | 保存模型输入/结果、任务状态和执行记录 | D/E |

## 实施时的固定决定

- 一个 Python 包、一套 MySQL 数据库迁移，SQLAlchemy 负责访问，Alembic 负责结构版本。
- D 运行唯一 FastAPI 及后台 worker；C 的任务以函数和 CLI 方式调用。
- 文件存持久化目录，数据库存记录和文件引用；所有数字有来源、原件、周期和导入批次。
- 原生数据与预测结果分开；月度不拆成周，缺失不填 0，不同指标不相加。
- 重复数据不重复入库；修订保留旧版本；后台发布的完整归属/锁保护是目标要求，当前缺口见 09。
- 12 日晚交可安装、可调用的依赖版，17 日完成全部约定范围，18 日联调缓冲。

## 第一版快速运行

准备一个 MySQL 8.4 数据库和最小权限应用账户，将真实连接地址写入当前终端的 `DATABASE_URL`。不要把密码写入仓库。

```bash
# 以下命令均从项目根目录执行
# 推荐直接安装交付 wheel；文件名以 release/ 中实际文件为准
python -m pip install ./data_foundation/release/anhui_data_foundation-0.1.6-py3-none-any.whl

# 在项目根目录运行迁移至0006
python -m alembic -c data_foundation/alembic.ini upgrade head

# 检查连接，写入五个指标及已核验的目录台账
data-foundation doctor
data-foundation seed-catalog --assets-dir data_foundation/assets

# 执行自动化测试
python -m pytest ./data_foundation/tests

# 运行交接样例，默认临时 SQLite 和合成资料，不使用现有业务数据库
python data_foundation/examples/de_handoff_smoke.py --report .tmp/c-de-handoff-local.json
```

开发环境也可运行 `python -m pip install -e ./data_foundation`，但需要环境中已有合适的 setuptools；离线环境优先使用 release wheel。

规范 CSV 的列和测试格式见 `examples/standard_observations.test-only.csv`。必须先通过公开 Python 接口登记真实实体、来源与原件，再运行：

```bash
data-foundation ingest-csv verified-data.csv \
  --source-id SOURCE_UUID \
  --asset-id ASSET_UUID

# 审核 dry-run 结果后才执行正式写入
data-foundation ingest-csv verified-data.csv \
  --source-id SOURCE_UUID \
  --asset-id ASSET_UUID \
  --apply
```

CLI 默认 dry-run。示例文件中的 UUID 和数值只用于测试，不得登记到正式库。
