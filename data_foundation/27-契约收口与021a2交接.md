- `catalog.list_entities(*, type=None, region_code=None, q=None, page=Page(), include_cameras=False)` 保持返回dict。region_code支持2/4/6位ASCII数字：省、市层级覆盖其下实体，区县六位精确；000000为全国。空字符串、通配符、非数字抛InvalidArgument。坐标可空，available能力仍仅来自已核验观测。

- `events.update_event(event_id, patch:dict, *, expected_version, operator_id, now)` 在行锁下比较正整数版本；冲突Conflict。source_id变化须同时给asset_id，任何来源/原件变更都校验最终归属。resolved/expired重新active须显式来源及不同新原件，允许同发布主体的新材料。拒绝无change_note、无效时间和空说明。主行/对象关系/历史同事务。
- get_event/create/update返回row_version和原始timeline历史行，历史行仍是version/snapshot/change_note/changed_at/operator_user_id。D映射HTTP时间线，不把推导字段误当作C存储列。

`list_events(*, region_code=None, status=None, now=None)` 仍返回list；其他HTTP筛选与分页当前由D补齐。Page最大100原已写入03/04，不是新约束。

## 2. 29号作业的C消费入口（不联网采集）

新增 `data_foundation.ingestion.run_ingestion_once(store, *, worker_id="c-ingestion-worker", job_id=None, lease_seconds=600)`，也可调用：

```bash
data-foundation run-ingestion-once --job-id <UUID> --lease-seconds 600
```

数据库与DATA_ROOT来自服务端环境。无到期匹配作业返回null/None；失败返回status=failed及稳定错误码，CLI退出1；旧lease失效抛LeaseLost，不失败新attempt。一次只领取type=ingestion，不领取E知识、视频或预测作业。

HTTP payload仅接受 `source_ids`（1—50个登记来源）与布尔dry_run（默认true），不接受文件路径或URL。每个来源由C资料管理员预先配置：

```json
{"adapter_key":"standard_csv","verification_status":"verified","adapter_config":{"csv_asset_id":"已登记CSV资产UUID","provenance_asset_id":"同来源证据原件UUID"}}
```

provenance_asset_id可省略，此时CSV本身作为证据原件。规范CSV与证据原件都须位于C DATA_ROOT、登记完整SHA/大小且归属同一来源。CSV必须text/csv或application/csv、UTF-8、单份≤32MiB；整项任务≤100000行。字段与既有import_standard_csv一致，原文定位保留在source_locator。配置属于可信服务端台账，不能从浏览器提交。

文件校验及解析在事务外；发布时锁当前job/attempt、来源及资产，复核登记和文件指纹，然后同一事务导入所有来源、写运行/质量报告、更新进度并完成job。结束前再次核验实时lease；超时或完成后异常使整批写入与完成一起回滚。dry_run仅保存审计和预览，不写观测；job.imported_count=0，result_refs.counts记录预览数量。坏行隔离并记录quarantined，不补零。

现有公开来源大多尚未配置csv_asset_id。对它们运行会明确failed，不假称已经实现所有官方来源的自动更新。新增网络来源、爬取、独立爬虫导入均不在本窗口。

**D Worker必须按职责筛选领取类型**：现行D代码无类型筛选会抢到ingestion并报“不支持”。D仅领取自己支持的knowledge_index/knowledge_reindex/knowledge_invalidate/video_analysis/visible_forecast；C本消费入口只领ingestion。D的29/30继续使用同一C jobs身份。D的HTTP202不是消费完成证据。

## 3. 已固定的D/E口径

- day_index以各假期首日100归一化；日数据须完整且同口径、首日非零。daily_average可用精确总量÷假期天数，或完整同口径daily_sum÷假期天数；缺天不能用已有天数分母。D需保留exact_total的source_ids，不能只从daily_points取来源。
- as_of认可D卡片最大实际period_end；全空时null，不新增仓储聚合接口。历史预测不足仍空点加reason，不拆分原生月值。
- P2PNet继续用C visible统一存储；配置、lease与原子发布真实签名见26号文档。get_counts未发布返回analysis_not_ready及空点，不暴露半成品。C原生状态与D HTTP状态映射分开记录。
- document_version与index_version分别绑定、不要求相等。D主路径严格loader有效；依赖ImportError也必须明确不可用，不允许回宽松snapshot。重建原件用get_document_file_ref；失效用knowledge.invalidate_document。
- 本轮运行范围P2PNet/PyTorch/CPU，阈值0.5；未评估manual_validation=null，60分钟预测不开放ready。无真实授权录像，实片/人工MAE/连续录像预测仍未验收。
