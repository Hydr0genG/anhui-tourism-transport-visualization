# C 与 D/E 的调用契约

设计版 0.2；v0.1.0 已实现身份、目录、来源、时序、假期事件、知识、录像计数、预测保存和作业的最小稳定入口。本文仍包含后续完整契约，未实现的扩展能力需以代码和[第一版交付记录](./07-第一版交付记录.md)为准。首轮冻结时记录 D/E 确认及包/迁移版本。根目录 HTTP 契约继续由 D 维护，C 不创建 HTTP 路由。

## 1. 包的使用方式

C 对外提供 `create_store`、输入/输出 DTO、枚举和业务错误。DTO 是固定字段的数据对象，可以理解为 Python 函数收发的“表单”。C 内部 ORM 模型不作为返回值，避免 Session 关闭后调用方仍触发查询。

当前基础使用方式如下；需要先完成迁移及目录种子：

```python
from data_foundation import create_store, SeriesQuery

store = create_store(settings.database_url)
with store.read() as reader:
    result = reader.observations.query_series(
        SeriesQuery(
            entity_id=entity_id,
            metric="scenic_visits",
            grain="month",
            start=start_date,
            end=end_date,
            quality="verified",
        )
    )
# result 是独立 DTO；由 D 转换为 HTTP 响应。

with store.write() as writer:
    writer.auth.revoke_session(id_hash=session_hash, now=utc_now)
# 正常退出统一提交，异常统一回滚。
```

一个工作单元共享一个事务，内部函数只 flush，不擅自 commit。`store.read()` 只暴露查询方法，并在退出时结束事务；`store.write()` 暴露约束写入。包级 read 能力是编程约束，不替代 D 的用户授权或数据库账户权限。

D 创建和配置 store；给 E 的服务注入 knowledge/video/short_forecast 所需接口及作业租约，不将完整 store 或认证仓储传给智能体。E 的数值工具由 D 注入，它调用 D 的受约束业务查询，再到 C 的 observations。

## 2. 所有函数共同遵循的规则

- 日期用 Python date；时间用带时区 datetime，入口拒绝不带时区的真实时间戳；进入数据库前转 UTC，读出恢复 UTC 时区。Decimal 保留精度，D 负责 JSON 数字序列化，不传 NaN/Infinity。
- ID 为 UUID；已有对象使用交接清单中的固定 UUID，不按姓名/名称动态生成新 ID。固定指标代码不改名。
- 列表输入 `Page(page=1, page_size=20)`，最大 100；输出 `PageResult(items, page, page_size, total)`。默认稳定排序为业务时间降序加 id，具体方法可规定不同顺序。
- 时序最多查询 20 年且返回不超过 10,000 个候选点；超出抛 QueryLimitExceeded，不能静默截断。该值是首版配置默认值，可按实测调整。
- 批量写入每次最多 1,000 个片段或计数窗口；导入行分批解析，业务提交边界按来源原件。首次来源规模控制在单原件 100,000 行内，超限先拒绝并登记，后续再设计分片提交。
- 外部传入的表名、SQL、任意排序表达式不接受。查询条件使用白名单字段和参数化语句。
- 通用 DTO 不包含密码哈希、会话材料、绝对磁盘路径；身份查询只向 D 的内部认证服务返回哈希。
- 来源详情按既有 HTTP 字段返回；时序 DTO 额外保留 `provenance`（观测版本、asset_id、原文定位、原文 URL）。D 在服务层保留这些内部追溯信息；若需要前端展示精确原文，可按兼容的可选字段扩展 HTTP 契约。
- 需要后台执行的写操作必须携带 `JobLease(job_id, attempt_no, lease_token)`；返回前在事务内校验租约，防止旧执行者覆盖新结果。

| 方法 | 输入 | 返回/语义 |
|---|---|---|
| `auth.create_user` | UserCreate(username, display_name, password_hash, role) | User；重复用户名为 Conflict；仅 D 离线管理员流程调用 |
| `auth.get_user_by_username` | 规范化 username | AuthUser 或 None；只有 AuthUser 含 password_hash |

Entity 的 available_metrics / available_grains 根据已有可用数据返回；未来计划支持的内容不宣称可用。用于区分“来源支持该粒度但当前区间没有数据”的能力信息由 C 的来源登记和选源策略维护，不能仅依据查询区间内有无点判断是否支持。

### 来源与原件内部入口

| 方法 | 输入 | 输出/用途 |
|---|---|---|
| `provenance.register_source` | SourceCreate | Source；C 台账和 D 已授权的资料上传流程使用，不能仅凭相同标题自动合并 |
| `provenance.persist_file` | 已校验的文件流、媒体类型、使用说明 | StagedFileRef；先落盘并返回相对路径、摘要和大小，不持有 DB 事务 |
| `provenance.register_asset` | source_id、StagedFileRef、URL、标题、发布时间、采集时间 | SourceAsset；按来源/摘要去重，属于调用方写事务 |
| `provenance.get_asset` | asset_id | 内部原件元数据；外部 DTO 过滤磁盘路径 |
| `provenance.resolve_event_asset` | source_id、asset_id? | 已核验的精确公告原件；只剩一个有效候选时可省略 asset_id，多候选抛 Conflict |

知识与录像上传由 D 校验后调用这些入口，再创建文档/录像记录。来源登记只表示建立台账，不自动授予公开回放权。人工文件和官方下载走同一原件留存方法。

现有事件 POST/PATCH 只有 source_id/new_source_id，不能保证在同一来源多个公告中定位唯一原文。因此提交 D 的兼容扩展建议为可选 `source_asset_id/new_source_asset_id`；旧请求只有在可唯一解析时成功，禁止自动取“最新一篇”凑来源。这是待 D 确认的 HTTP 契约补充，尚未修改根目录接口或实现路由。时序响应可选 provenance 扩展同样待 D 确认。

## 4. 历史时序与专题查询

### `observations.query_series(SeriesQuery) → SeriesResult`

输入：entity_id、metric、grain(day/week/month)、start、end、quality(verified/all，默认 verified)。holiday 通过单独的专题查询读取，不进入普通趋势接口。

输出：

```text
SeriesResult
  entity: EntitySummary
  metric: Metric
  grain: day | week | month
  points: ObservationPoint[]，按 period_start、source_id、id 升序
    id, version, metric, value, unit, period_start, period_end, grain
    source_ids, published_at（可空）, ingested_at, quality_status
    provenance: {source_id, asset_id, source_url, source_locator, run_id}
  missing_periods: [{period_start, period_end}]
  coverage_ratio: Decimal，范围 0—1
  diagnostics: [{code, period_start?, period_end?, message}]
  selection_policy_version: string 或 NULL
```

规则：先校验实体与指标、来源支持粒度，再列出请求范围内完整周期，再按选源策略及质量筛选。verified 返回每期至多一个点；all 可返回多个候选，必须保留来源标识；coverage_ratio 两种模式都仅统计已解决选源且 verified 的周期。

例如月查询覆盖 2026-01-01 至 2026-03-31，应有 3 期，真实核验数据只有 1 月和 3 月，则 points 为 2 条，missing_periods 指出 2 月，coverage_ratio 为 2/3。该例只解释计算方法，不代表当前已有这些数据。

如果只支持 month 却请求 week，抛 UnsupportedGrain；支持 month 但所选区间没记录，正常返回空 points、对应缺期及覆盖率 0。请求边缘不足完整月时不合成“半月值”，通过 diagnostics 说明被排除的边缘。

### 其他历史与专题方法

| 方法 | 输入 | 返回/分工 |
|---|---|---|
| `observations.get_coverage` | SeriesQuery | CoverageReport：应有/可用期数、缺期、最长连续段、最大缺口、口径断点、最近发布/入库日期 |
| `observations.get_latest_verified` | entity_id, metric, grain, as_of | ObservationPoint 或 None；只能返回 period_end≤as_of 的完整周期 |
| `observations.query_holiday_values` | entity_id, metric, holiday_id | HolidayEvidence：精确假期总量（如有）、日序列、缺失天数、来源与口径 |
| `holidays.list_holidays` | year?, kind?, region_code? | Holiday[]，start_date 升序 |
| `holidays.get_holiday` | holiday_id | Holiday，含定义来源和适用学校/地区 |

D 决定 overview 卡片、比较模式、同比计算及预测。C 提供证据和缺失信息：精确同区间假期总量可以支持 period_total；完整假期总量÷实际天数可作为比较用的 daily_average，但不能回填为逐日观测；day_index 必须有完整日数据。寒暑假比较必须核对地区/学校范围，不能仅按 kind/year 配对。

## 5. 事件与知识资料

| 方法 | 输入 | 返回/事务要求 |
|---|---|---|
| `events.list_events` | 与 HTTP 相同筛选项、Page、now | PageResult[EventSummary]；有效期筛选和 status 同时考虑 |
| `events.get_event` | event_id | EventDetail，含历史时间线与来源 |
| `events.create_event` | EventCreate、operator_id、now | Event；核验官方来源，主表/影响对象/首条历史同事务 |
| `events.update_event_with_history` | event_id、EventPatch、expected_version、operator_id、now | Event；版本不符 Conflict；变更说明必填 |
| `knowledge.register_document` | DocumentCreate（HTTP 元数据＋已留存 asset_id） | Document；原件已持久化才登记；上传任务由 D 一起入队 |
| `knowledge.get_document/list_documents` | document_id / filter, Page | Document / PageResult；带 active_index_version，不暴露受限路径 |
| `knowledge.begin_index` | document_id、version、parser_version、embedding_model_version、JobLease | IndexBuild；同版本重试可复用未完成构建 |
| `knowledge.write_chunks` | index_id、ChunkInput[]、JobLease | BatchWriteResult；同序号同摘要跳过，不同摘要冲突 |
| `knowledge.activate_index_version` | document_id、version、artifact_ref、expected_chunk_count、JobLease | Document；校验片段数、产物摘要和归属后原子切换 |
| `knowledge.fail_index` | index_id、错误摘要、JobLease | 保持原 active_index_version，标记本次失败 |
| `knowledge.get_chunks` | document_id、version?、Page | 未给 version 使用当前有效版本；没有可用版本返回空及 index_not_ready 原因 |

批量重建多个文档时每个文档独立发布，作业结果列出成功/失败文档；不声称全部同一时刻切换。索引生成、文档解析、embedding 和引用组织由 E 负责，C 不调用大模型。

同一版本重试只能继续写入相同片段内容；解析器、切分或 embedding 配置发生变化必须使用新版本。同样，视频配置摘要还应包含 E 的分析流水线版本；算法代码改动产生不同结果时不得继续向原分析追加冲突计数。

## 7. 预测保存

`forecasts.save_history_forecast(HistoryForecastInput) → ForecastRun`：输入包含字段字典列出的训练范围、模型配置、实际输入快照、回测、状态和全部结果点。运行与结果点一次事务保存；C 验证来源、版本、周期和区间，D 负责预测算法与不足判定。

`forecasts.save_short_forecast(ShortForecastInput) → ShortForecastRun`：校验分析成功、输入截止时间、方向及 horizon/step；清单中所有窗口必须在 cutoff_at 前结束。E 负责质量判定及误差计算。

`get_history_forecast(run_id)` / `get_short_forecast(run_id)` 返回完整运行与点。不足状态必须带 reason 且 points=[]，不能以 0 值伪造预测。当前公开 HTTP 没有单独“读取历史 run”的路由，内部方法供 D/E 复现和复用，不要求新增路由。

## 8. 任务与导入

| 方法 | 输入 | 输出 |
|---|---|---|
| `jobs.enqueue_or_get` | JobCreate(type, idempotency_key, payload, requested_by?, reason) | Job；同键复用，payload 不一致则 Conflict |
| `jobs.claim_job` | worker_id、now、lease_seconds | ClaimedJob(Job, JobLease) 或 None |
| `jobs.heartbeat` | JobLease、now、lease_seconds | 新到期时间；租约不匹配抛 LeaseLost |
| `jobs.update_progress` | JobLease、processed_count、imported_count | Job；使用绝对计数避免重试累加两次 |
| `jobs.complete_job/fail_job` | JobLease、result_refs / error_summary | Job；只有当前有效尝试可结束 |
| `jobs.recover_expired` | now、max_attempts | 恢复数量；标记旧尝试 expired，未超限回 queued，否则 failed |
| `jobs.retry_failed` | job_id、reason、operator_id、now | Job；显式恢复到 queued，保留旧尝试 |
| `jobs.get_job` | job_id | Job；D 过滤内部 payload、租约和路径再返回 HTTP |
| `check_due_sources` | now | SourceCheckRequest[]；本函数只规划，不启动进程 |
| `run_ingestion` | source_ids、dry_run、reason、JobLease | IngestionSummary，各来源/原件的结果列表 |

JobLease 失效属于内部执行冲突，由 worker 停止写入，不直接作为用户 HTTP 业务错误。任务业务函数运行长操作时不持有数据库事务；用短事务更新心跳、批次与结果。任务失败可有先前来源已成功提交，Summary 明确列出，不承诺跨 50 个来源的大事务。

## 9. 业务错误与 D 的映射

| C 错误 | D 的处理 |
|---|---|
| InvalidArgument | 400；HTTP 字段验证由 D 自身按框架契约处理 |
| NotFound | 404 |
| UnsupportedGrain / MetricEntityMismatch / InvalidPermission | 422；用户没有操作权限则由 D 返回 403，区别于无效授权资料 |
| Conflict / AnalysisNotReady | 409 |
| QueryLimitExceeded | 422，说明缩小范围 |
| StorageUnavailable | 503，统一错误响应，不泄露数据库异常或连接信息 |
| LeaseLost | worker 停止旧尝试，内部日志留痕 |

错误提供稳定 `code`、可读 message 和非敏感 details。401、403、429 由 D 的认证、授权和限速产生。C 不负责伪造 HTTP response。

## 10. 冻结前对接清单

- D：确认身份字段与 CSRF 实现不缺数据；同步仓储接入方式；HTTP 字段映射；任务领取/心跳/恢复职责。
- E：确认片段 locator、索引产物引用、检测模型摘要、进出方向、窗口边界、人工样本和预测输入快照格式。
- C：提供可安装包、迁移、DTO、错误类型、独立测试数据和 D/E 示例；本文函数不能以 `pass` 或固定假结果作为交付。
- A/B：通过 D 获取正常/空/不支持粒度/待处理/失败示例；不需要导入 Python 包或接触 MySQL。

所有新增签名属于设计建议，尚未声称已获组员确认。首轮交接后，同名函数保持兼容；必须改动时更新契约版本与接收方迁移说明。
