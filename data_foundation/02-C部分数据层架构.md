# C 部分数据层架构

状态：2026-10-10 设计版 0.2；第一版代码 v0.1.0 已实现。继承根目录[项目架构](../04-项目架构与文件树.md)与[HTTP 契约](../03-接口总览.md)。尚未由 D/E 确认的扩展字段仍是拟定契约，需在首轮联调中冻结。

本文是总览；实施细节分别见[数据库字段字典](./03-数据库字段与关系字典.md)、[D/E 调用契约](./04-DE调用契约.md)、[流程运行与验收](./05-数据流程运行与验收.md)。第一次阅读先掌握“来源→原件→数值→查询”这条主线；表字段和函数不需要一次背完。

## 1. 架构决定与职责

**C 交付一个可安装的 Python 数据包、一套 MySQL 迁移和一条可重复执行的数据处理流程。**不独立启动 HTTP 服务。D 的 FastAPI 和后台 worker 安装并调用 C 的包；A/B 通过 D 获取数据。

采用 Python + SQLAlchemy + Alembic + MySQL，沿用现有 MySQL/Alembic 规划，数据库实施目标为 MySQL 8.4。首版采用同步仓储，D 负责将数据库调用安排在适合同步 I/O 的执行位置。数据库连接地址由环境变量传入，依赖补丁版本在首次可运行后锁定；不额外引入分布式队列或数据平台。

```text
官方统计 / 公告 / 授权资料 / 录像
                    ↓
来源登记 → 原件留存 → 解析与标准化 → 质量检查 → 事务入库
                                                ↓
                MySQL（业务记录、版本、批次、来源）
                文件目录（原件、知识资料、授权录像）
                                                ↕
           C 的公开数据访问包：受约束查询 + 业务写入
                     ↙                          ↘
        D：API、认证、历史预测             E：文档与录像处理
                     ↓                          ↓
           A/B 页面、智能体数值工具       片段、计数、短时预测回写

D 的唯一后台 worker → 调用 C 的每周检查和导入任务
```

责任边界：C 维护包括用户、会话、预测和作业在内的全组库表。D 负责密码哈希、会话生成、权限、HTTP 错误映射、事件业务规则、预测算法及任务调度进程；E 负责切分/检索/索引生成、视觉与短时预测。C 的 Python 包不是独立权限边界，D 必须先鉴权，E 仅得到所需的窄接口。

现有文档对智能体数值查询路径有两种描述，首版统一采用 **E 智能体 → D 注入的受约束数值工具 → C 查询**，满足 HTTP 契约的数值来源要求。E 的文档/视频处理可以直接调用 C 的指定仓储；不把任意 SQL、用户或会话仓储开放给智能体。

## 2. 分层与文件组织

| 层 | 负责什么 | 允许依赖 |
|---|---|---|
| contracts | 固定的输入/输出 DTO、枚举、错误 | 基础类型，不依赖数据库或 FastAPI |
| public / services | 给 D/E 的入口，控制事务与业务校验 | contracts、repositories、provenance |
| db / repositories | 表结构、约束、受约束查询和写入 | contracts、SQLAlchemy，不导入 D/E |
| ingestion | 获取、解析、标准化、质量核验与导入 | 适配器、数据服务，不绕过写入规则 |
| scheduling / cli | 规划任务、调用统一处理流程 | public/任务服务；不复制采集业务 |
| provenance | 管理原件、授权与文件定位 | 文件存储和相关仓储 |

依赖从外层向数据层走；C 不导入 `api_platform` 或 `intelligent_analysis`，避免互相循环引用。模型只描述存储，不承担预测或 HTTP 业务。

## 3. 数据模型与关系

实体、来源、批次、文档、视频等业务 ID 使用稳定 UUID；指标使用既定代码。统计日历日期使用 `DATE`，真实时间戳按 UTC 存储，输出由 D 转为带时区时间。月份/周的统计日期不做 UTC 日期偏移。

### 3.1 基础、认证与观测

| 表/关系 | 关键字段与约束 | 提供给谁 |
|---|---|---|
| `users` | `id, username(unique), display_name, password_hash, role, status` | D；C 只存密码哈希 |
| `sessions` | `id_hash(unique), user_id, expires_at, revoked_at`；CSRF 机制由 D 定义 | D；只查询未撤销、未过期且用户有效的会话 |
| `entities` | `id, name, type, region_code, longitude, latitude, status`；`type` 包含 camera，摄像头关联所属景区 | D/E；公开目录由 D 排除 camera |
| `metrics` | `code, display_name, definition, unit, supported_entity_types, aggregation_rule, comparability_note` | 全组字典 |
| `sources` | 发布单位、标题、URL、发布时间、覆盖期、实际粒度、使用条件、核验状态、更新频率、最近检查时间 | D/E；来源台账 |
| `source_assets` | 持续来源的每一期原件：原文 URL、文件摘要/路径、发布/采集时间 | C/D/E；不可变快照 |
| `ingestion_runs` | 来源、作业、开始/结束、状态、原件引用、处理规则版本、新增/修订/跳过/隔离数量、错误摘要 | C/D；每次检查均有记录 |
| `quality_issues` | 批次、问题定位、类型、严重程度、隔离内容和处理结果 | C；复核与质量报告 |
| `observations` | 对象、指标、起止日期、粒度、数值、标准单位、来源、批次、发布时间、入库时间、质量状态、原文定位、口径版本 | D；实际观测，不放预测 |
| `observation_revisions`（补充） | 观测 ID、旧值/新值、旧/新批次、修订理由和时间；保存完整旧记录快照 | C/D；修订追溯 |
| `series_policies`（补充） | 对象、指标、粒度、适用期、选用来源、选择依据 | C/D；多来源选取，不重复求和 |

观测唯一键沿用团队约定：`(entity_id, metric_code, period_start, period_end, grain, source_id)`，所有键字段非空。常用查询索引覆盖对象、指标、粒度和起始日期。`value` 用定点数保存并保留原始单位和换算因子；未知量不写成 0。

同一来源同一周期出现修订时，在一个事务内保存旧版并更新当前记录。口径变化必须保留新旧说明；无法比较的数据段不拼为连续可比序列。不同来源的同周期记录可并存，但查询按显式选源规则输出一个主序列；未解决的来源冲突不进入默认 verified 序列，并返回质量原因。

### 3.2 假期、事件、知识

| 表/关系 | 关键字段与约束 |
|---|---|
| `holidays` | 种类、名称、年份、起止日期、天数、地区/学校适用范围、定义来源；不将寒暑假统一成全省固定日期 |
| `events`、`event_history` | 类型、official/model_signal、级别、状态、影响对象、有效期、发布日期、最近核验时间、来源及每次变更说明 |
| `event_entities`（关联表） | `(event_id, entity_id)` 唯一，支持按对象筛选 |
| `knowledge_documents` | 来源、发布/生效/失效时间、使用说明、文件路径/摘要、文档版本、索引状态、当前生效索引版本 |
| `knowledge_indexes` | 每次索引版本、产物摘要/路径、模型版本、作业及状态 |
| `knowledge_chunks` | 索引 ID（关联文档与版本）、片段序号、文本/文本定位、页码或段落；组合键唯一 |
| `document_entities`（关联表） | 文档与适用对象的关联 |

RAG 向量索引及其生成由 E 管理，C 保存引用元数据和当前版本指针。新版本片段写入完成后再切换指针，失败时保留旧版可读。文档过期判定结合适用日期，E/D 决定是否使用并提示。

### 3.3 视频、预测与作业

| 表/关系 | 关键字段与约束 |
|---|---|
| `permission_records`（补充） | 授权方/使用依据、证明定位、允许用途、有效期、能否回放；没有有效依据不能登记为可用录像 |
| `videos` | 景区、摄像头、录制起止、文件摘要/路径、授权记录、状态；结束必须晚于开始 |
| `video_analyses` | 视频、检测权重版本/摘要、OpenVINO 版本、设备、跟踪配置、计数线、方向、时间窗、配置摘要、作业和状态 |
| `camera_counts` | `analysis_id, window_start, window_end, entries, exits, quality_status`；`(analysis_id, window_start, window_end)` 唯一；非负整数 |
| `manual_annotations`（补充） | 视频/摄像头、时间窗、人工进出数、标注人、方向说明、复核状态；E 用于误差评估 |
| `forecast_runs`、`forecast_points` | D 的历史预测运行与结果：训练窗、输入数据版本清单、模型版本、回测信息、状态、目标周期、点值/区间 |
| `short_forecast_runs`、`short_forecast_points`（补充结果表） | E 的短时预测：分析 ID、截止时间、方向、步长、预测长度、模型版本、验证误差、状态及结果点 |
| `jobs` | type、status、进度/计数、执行起止、错误摘要、结果引用、幂等键、执行尝试/心跳；用于三类既定后台任务 |
| `job_attempts` | 每次执行的序号、worker、租约、心跳及结束原因；旧执行者不能覆盖新结果 |

输入数据版本清单记录实际输入值、所用观测版本/摘要或计数分析版本，使来源修订后仍能复现预测输入。C 保存 D/E 提供的模型元数据，不计算模型误差。

这些补充表用于落实既有“修订留痕、授权、标注和预测可追溯”的要求，不增加面向用户的功能范围。10 日冻结必需字段，11—12 日交全部依赖表的最小迁移；后续只用新增迁移完善索引和约束，不修改已交付的迁移历史。

## 4. 对 D/E 的公开 Python 契约

统一入口拟为 `create_store(database_url)`，通过 `store.read()` / `store.write()` 提供短生命周期工作单元及以下方法组；方法名在 12 日前冻结。DTO 与错误类型从公开入口导出，避免外部绑定内部 ORM。下表是核心入口摘要，完整签名、补充方法与错误语义以[调用契约](./04-DE调用契约.md)为准；尚非可运行代码。

| 模块 | 最小函数/方法 | 调用者 |
|---|---|---|
| auth | `get_user_by_username`、`create_user`、`save_session`、`get_active_session`、`revoke_session` | D |
| catalog | `list_entities`、`list_metrics`、`get_source` | D |
| observations | `query_series(SeriesQuery)`、`get_coverage(SeriesQuery)`、`get_latest_verified` | D 的业务层/数值工具 |
| holidays/events | `list_holidays`、`get_holiday`、`list_events`、`get_event`、`create_event`、`update_event_with_history` | D |
| knowledge | `register_document`、`get_document`、`list_documents`、`write_chunks`、`activate_index_version` | D/E |
| video | `register_permission`、`get_permission`、`register_video`、`get_video`、`list_videos`、`create_analysis`、`write_counts`、`query_counts`、`write_manual_annotations` | D/E |
| forecasts | `save_history_forecast`、`get_history_forecast`、`save_short_forecast`、`get_short_forecast` | D/E 各自结果 |
| jobs | `enqueue_or_get`、`claim_job`、`update_progress`、`complete_job`、`fail_job`、`get_job` | D worker/C/E 任务 |
| ingestion | `run_ingestion(source_ids, dry_run, reason)`、`check_due_sources(now)` | C CLI/D worker |

`SeriesQuery` 必含 `entity_id, metric, grain, start, end`，可带 `quality=verified|all`，默认 verified。只允许已知指标、日期和对象；设置查询时间跨度/行数上限，禁止传 SQL。返回 `entity, metric, grain, points, missing_periods, coverage_ratio`，点包含 HTTP 契约要求的来源、时间、单位和质量字段。

C 返回业务 DTO，不加 `data/meta/request_id` HTTP 外壳。D 负责分页外壳、序列化与状态码：`UnsupportedGrain`、`MetricEntityMismatch` 映射 422，`NotFound` 映射 404，`Conflict/AnalysisNotReady` 映射 409。无数据是成功的空结果；`data_insufficient` 由 D/E 预测服务判定。

所有仓储方法共享调用方明确创建的工作单元，不在仓储内部各自提交。工作单元成功提交，异常回滚并关闭 Session。采集失败后的批次失败记录单独用新事务保存。每个请求/作业使用独立 Session，避免跨线程复用；事务范围参考 [SQLAlchemy 官方说明](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html)。

## 5. 数据处理与质量规则

1. **登记来源。**先记录发布单位、链接、使用条件、对象/指标、粒度和可用时间；来源不明的数值不进入 verified 数据。
2. **保存原件。**抓取或手工导入后保存原件摘要、获取时间、原文页码/表格/段落位置及解析器版本。网络获取完成后再开启业务写入事务。
3. **标准化。**统一对象 ID、单位和日期，保留原始文字及换算依据。“累计截至某月”不得直接当该月值；首版不自动拆分累计量，后续若支持求差，必须满足同口径和完整性条件并记录派生依据。
4. **校验。**检查唯一键、非负数、单位、周期边界、实体指标匹配、来源可用性、异常变化及口径断点。异常值先标记复核，不自动删除或平滑。
5. **幂等写入。**通过文件/内容摘要识别无变化，数据库唯一约束兜底。相同业务键相同值跳过；值变化且确认是来源修订时写修订历史；无法确认时隔离待审。
6. **提交与报告。**业务数据、修订记录和批次结果一致提交；输出新增、修订、跳过、隔离、缺失统计和检查时间。格式损坏导致全批失败；可独立定位的坏行允许隔离，但报告必须明确成功行与问题行。

质量枚举拟定为 `verified | pending_review | rejected`；缺期由 `missing_periods` 表示，不能用质量枚举代替缺期。目录中的可用粒度来自实际来源/数据能力，不根据 UI 需求生成。

日/周/月统计日期采用闭区间；视频时间窗采用 `[start, end)`，避免边界重复计数。周为周一至周日、月为自然月。首版只发布原生观测；派生聚合是后续可选能力，仅在完整、可加且同口径时启用，月转周及假期总量拆日一律拒绝。日数据不足时不声称完整周/月总量。

覆盖率 = 请求范围内“完整周期且通过核验的已选源周期数”÷“应有完整周期数”，分母为 0 时返回 0 并说明没有完整周期；请求边缘不完整周期不算完整观测。假期覆盖单独按专题定义计算。观测缺失不填 0，真实 0 必须有来源依据。

首批质量报告至少包含对象/指标/粒度、起止、周期数、缺期列表、覆盖率、最长连续段、最大缺口、口径变化、最新发布时间、未核验条数及原件可追溯比例，供 D 判断可否预测。

## 6. 周更新与异步作业

- D 运行唯一后台 worker，C 导出任务函数；不在 FastAPI 每个进程中各启动一个定时器。首版每周一 09:00（Asia/Shanghai）检查来源，此时间为拟定默认值，可配置；周检查不等于生成周数据。
- D 调度器调用 `check_due_sources`，使用“来源＋计划检查时段”幂等键入队，再调用导入任务。手动触发和定时检查使用相同流程。
- 作业正常状态为 `queued → running → succeeded/failed`；领取通过事务与租约保证当前执行者唯一。超时在重试额度内回 queued，failed 可由管理员显式重试；均沿用逻辑作业并增加尝试记录。发布结果时核验当前租约，旧执行者不得写入。
- 每次来源检查都写批次。内容无变化：`succeeded` 且 `imported_count=0`；网络或解析失败保留错误摘要并按有限重试策略处理，不覆盖旧数据。
- `dry_run=true` 可以保留原件、检查日志和作业记录，但不能写入/修订业务观测；返回预计变化及问题清单。
- 视频分析的重复键包含视频内容摘要、检测权重摘要、运行时版本、设备、跟踪配置、计数线、方向和时间窗，确保同输入同配置复用作业，不混用不同分析结果。文件相同但解析/清洗/质量规则升级时允许重新处理，不能仅凭原件摘要跳过。

## 7. 迁移、交付和验收

发布 v0.1.0 时一起交包版本、迁移版本、数据字典版本和样例版本。D/E 只依赖公开函数；冻结后优先新增可选字段，不重命名旧字段。必须破坏兼容时，先更新契约并通知 D/E，各自在自己目录修改。

Alembic 是唯一建表/升级路径；从空库及既有交接版本各验证一次。生产式联调使用 MySQL，不能只靠 SQLite 验证数据库约束。迁移创建和执行方式依据 [Alembic 官方教程](https://alembic.sqlalchemy.org/en/latest/tutorial.html)；具体运行命令写入实施后的 README，目前不把未实现命令宣称可用。

核心验收场景：重复导入不增加记录；修订保留旧版；失败回滚不留半批；不同来源不重复求和；缺失不变成 0；不支持粒度被拒绝；过期/撤销会话不可读为有效；时间边界无重计；同分析计数重传不重复；索引失败仍可读旧版；无授权录像不标记可用；空库可重建。

首轮交付优先使全部依赖存储真实可用，并纳入少量真实资料；第二轮补齐来源适配、质量治理、定时更新和完整材料。各日期与验收点见[交付计划](./01-C部分交付计划.md)。
