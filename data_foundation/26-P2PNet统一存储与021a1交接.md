# C 0.2.1a1：P2PNet统一存储、原件入口及D/E交接

日期：2026-10-16。用户已明确选择“C统一存储”。本版只修改C，不修改D/E仓库，不推进独立爬虫。

## 1. 版本、迁移和职责

- 包 `anhui-data-foundation==0.2.1a1`；迁移 `0006 → 0007`，C业务表由31增为34。
- 新增 `visible_analyses`、`visible_count_points`、`visible_forecasts`。旧 `video_analyses`、`camera_counts`、旧预测、标注及其签名保留，不填虚构计数线/方向/OpenVINO版本，也不搬移旧数据。
- C是新分析和结果的唯一权威存储；D保留编排和必要审计，不再以D私表的人数结果作为正式来源。既有D私表数据不要自动删除；如何保留/迁入由D另交清单。
- E的模型校验、真实权重加载和计算仍由E负责；C校验已提交结果的配置、时刻、范围、样本、中位数、来源及租约，不声称存储测试证明模型准确。
- 升级前做数据库/受管理文件备份，并停止写入后在维护窗口迁移。以新ZIP中 `alembic.ini` 和迁移文件执行 `python -m alembic -c ... upgrade head`。wheel本身不含迁移和外部样例，不能只装wheel就当数据库已升级。
- 0007只建新表，不改旧列。降级仅允许3张新表均为空时进行；有结果则拒绝删除，需先明确导出和迁回方案。禁止用 DROP 或清库完成验收。

## 2. 支持矩阵（真实方法名）

| 能力 | C入口与边界 |
|---|---|
| 视频登记 | 现有 `uow.provenance.register_source/register_asset`、`uow.video.register_permission/register_video`；来源/景区/机位先登记，原件先通过 `store.persist_file` 落盘，再在事务内登记资产、授权和录像 |
| 视频列表/回放 | 现有 `uow.video.list_videos(..., page=Page(...))` 返回 `{items, page:int, page_size:int, total:int}`；`get_playback_ref(video_id, now)`保留404/403/409对应异常族；D负责用户对象授权、Range和HTTP白名单 |
| P2P分析登记 | `uow.visible.create_analysis(video_id=..., job_id=..., config=..., provenance=..., analysis_id=None, now=None)`；只允许queued的`video_analysis`任务；可传D已分配的规范UUID，之后以C返回身份为准 |
| 授权分析原件 | `store.get_visible_input(analysis_id, lease, now=None)`：按analysis用途校验，而非要求允许回放；返回E所需`file_path/config/source_ids/recorded_start_at/recorded_end_at`等内部字段 |
| 开始/分批人数写入 | `uow.visible.begin_analysis(analysis_id, lease, now=None)`；`write_points(analysis_id, points, lease, now=None)`，单批≤1000，结果为`{inserted, skipped}` |
| 发布并完成任务 | `uow.visible.complete_analysis(analysis_id, expected_point_count, lease, manual_validation=None, now=None)`；方法内部同时发布结果、更新录像并完成C jobs，外层D**不得再complete_job一次** |
| 失败并完成失败状态 | `uow.visible.fail_analysis(analysis_id, error_summary, lease, now=None)`，内部同步失败分析和任务；旧lease不能覆盖新尝试 |
| 人数读回 | `uow.visible.get_counts(video_id, analysis_id, now=None)`，E原生CountsResponse形状；未发布返回`analysis_not_ready`、空points和空analysis/ROI，不暴露半成品 |
| 分析溯源 | `uow.visible.get_analysis(analysis_id, now=None)`；含C身份、冻结配置、原件/录制时间快照及本次provenance；内部形状不直接回HTTP |
| 预测输入 | `uow.visible.forecast_input(analysis_id, cutoff_at, now=None)` 返回截至cutoff的5min历史、input_manifest及input_sha256，不包含未来点 |
| 预测存储 | `uow.visible.publish_forecast(analysis_id=..., cutoff_at=..., horizon_minutes=..., input_sha256=..., result=..., lease=..., now=None)`；必须使用独立`visible_forecast`任务，payload含analysis_id/cutoff_at/horizon_minutes；内部原子完成作业 |
| 预测读回 | `uow.visible.get_forecast(forecast_id, now=None)`，含输入身份/摘要及E原生result；D按公共响应映射，不自行计算预测 |
| 知识原件 | `store.get_document_file_ref(document_id)`；取C登记asset和document_version，校验完整SHA/大小及安全路径；**D先做文档权限过滤** |
| 索引显式失效 | `uow.knowledge.invalidate_document(document_id=..., reason=..., operator_id=..., lease=..., now=None)`；D提交`knowledge_invalidate`任务，requested_by须是同一有效管理员；payload含document_id；内部完成任务并写审计结果 |
| 人工真值 | 本轮支持真实评估摘要`manual_validation={sample_count,mae}`；未评估必须null。逐帧真值原件可走来源/资产留存，但没有把旧entries/exits标注表伪装为新人数标签表 |

完整视频登记顺序：C目录实体与来源 → `persist_file`（事务外）→ 同一业务事务登记SourceAsset、PermissionRecord、Video。授权证据必须真实，`status=approved`只能由具备权限的流程确认，不能用测试fixture作授权凭证。录制起止由素材方提供，不采用上传时间。

文件输入校验先退出短事务，再读取原件计算SHA，最后重新核验租约、授权及登记指纹；处理期间仍须由D独立心跳续租。返回的file_path/asset内部字段仅供Worker，不能出现在HTTP。已核验引用不是对之后解码的文件锁，输入须保持不可变，发生变化时拒绝并重新登记。

## 3. P2PNet原生口径

配置须完整提供8项：`count_model=p2pnet`、`weights_version`、E原生`roi.points=[{x,y},...]`、`sample_interval_seconds`、`aggregation_minutes=5`、`confidence_threshold=0.5`、`inference_engine=pytorch`、`device=CPU`。只接受已验证CPU口径；不填旧OpenVINO字段。

provenance至少提供本次实际模型的7键：count_model、weights_version、weights_sha256（完整64位）、model_source_revision、confidence_threshold、inference_engine、device。可附sample_interval_seconds/aggregation_minutes/torch_version/runtime_version/cuda_available；与配置冲突或含未知键则拒绝。D应取实际counter.provenance并绑定本次analysis，不借当前模型信息装饰旧分析。

人数点保留E原生`camera_visible_people`、“人”、frame或5min；value允许小数且必须有限非负，数据库使用双精度而不是旧进出整型。帧记录真实时刻；5min保留窗口起止、median、有效样本数及good/degraded/unavailable。缺失为null及0有效样本，不能填0。

该指标由`uow.visible`人数领域提供，不塞入普通`observations`的day/week/month序列，也不替换旧指标字典的camera_entries/exits。D应在公共指标说明中区分来源和原生粒度，不能调用普通query_series对画面人数作人次求和。

**窗口以真实recorded_start_at为锚点**，与E 0.6.0一致，不强行改为自然时钟的00/05分钟。完整5分钟窗须全部提交，即使缺帧也要显式unavailable。C在发布前核对窗口中位数、样本数和质量与本次已存帧一致；未完成的尾窗不伪造。

同采样槽/同窗口相同内容重传skipped，冲突则拒绝整批，不先删旧点。失败或过期重领后，先用新lease begin_analysis，再重传相同结果；错误的未发布结果需显式重建新analysis，不靠无审计覆盖修正。

预测保存输入指纹、cutoff、analysis、模型/回测、不足状态及可空上下界。ready要求当前实现至少17/32个连续完整5分钟点及≥3折回测，不差于保持最新值基线；这是存储放行约束，不是C重新实现E预测。60分钟仍不开放ready；可保存data_insufficient及空预测。未评估人工MAE为null，不写0样本/0误差。

## 4. D Worker最小接线顺序

```python
# API：先按实际counter校验配置/权重，登记C job及稳定analysis身份。
with store.write() as uow:
    analysis = uow.visible.create_analysis(
        video_id=video_id, job_id=job_id, analysis_id=analysis_id,
        config=e_native_config, provenance=actual_counter_provenance,
    )

# Worker：领取并退出短事务；输入核验中的文件IO在事务外。
ref = store.get_visible_input(analysis_id, lease)
with store.write() as uow:
    uow.visible.begin_analysis(analysis_id, lease)
result = process_video_job(ref, counter=counter)  # E计算在事务外，D另行续租。
for batch in batches_of_at_most_1000(result['points']):
    with store.write() as uow:
        uow.visible.write_points(analysis_id, batch, lease)
with store.write() as uow:
    uow.visible.complete_analysis(
        analysis_id, len(result['points']), lease,
        manual_validation=result.get('manual_validation'),
    )  # 已完成C job；D外层不再重复complete。
```

上述变量来自D已有编排，`batches_of_at_most_1000`是伪代码分批说明，不是声称C新增了同名函数。E函数签名以固定0.6.0为准。D负责把公开`[[x,y],...]` ROI转换为E原生x/y对象；27顶层审计扩展由D从C的本次provenance白名单添加，不传进E严格CountsResponse。

## 5. 知识版本与失效入口

`document_version`是C已登记的原文版本，应读取后透传；`index_version`是新建索引版本。分别在各自记录/产物中一致，但二者不要求相等。固定资料有`sha256:<32位前缀>`版本标识，原件完整性始终另用64位SHA；不把某个示例版本算法升级为全局强制规则。

`get_document_file_ref`是原件入口；`get_index_artifact_ref`仍只用于索引产物。重建使用前者或同等可验证原件，不只按staging文件名寻找后便用旧原文版本签名。

显式失效保留旧文件、索引和最后版本指针，仅将文档index_status置failed，审计写入该管理员任务result_refs。默认活动读取返回index_not_ready；管理员显式按旧version读取仍可做审计，D不得将其作为当前默认答案。恢复需新建唯一索引版本并正常激活，不在loader中静默跳过坏文档或降级旧内存。D需增加对应管理作业分支；C不另起消费者。

## 6. 历史数值工具与接收边界

交付的 `examples/c_readonly_metric_tool.py` 是C侧只读参考适配，使用C现有query_series；不是已经修改D的19号接口。支持一个服务端授权对象、完整原生day/week/month周期，外部区间定义为[start,end)，按+08业务日转成C的闭区间date。不拆月、不跨对象默认求和；缺覆盖、无权限或未支持时无value/source_ids，避免半个成功。

最低真实样例为合肥新桥机场2025年1月：1,111,644人次；资料来自C既有快照，不是独立爬虫导入。历史值不能证明当前现场人数。D的public station类别须映射到C的airport/rail_station类型。
