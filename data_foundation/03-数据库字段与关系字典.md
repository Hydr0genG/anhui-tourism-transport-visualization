# C 数据库字段与关系字典

设计版 0.2，2026-10-10。第一版已将本文 30 张表实现为 SQLAlchemy 模型和四段 Alembic 迁移；真实 MySQL 服务验收仍待 D 的联调环境。总体职责见[架构总览](./02-C部分数据层架构.md)，函数输入输出见[调用契约](./04-DE调用契约.md)。新增的内部表不会自动增加 HTTP 接口。

## 1. 先理解数据库里存什么

例如“某景区某月接待了多少人次”，要拆成：

```text
entities：哪个景区？
metrics：统计的是什么，单位是什么？
sources：哪个持续发布的数据来源？
source_assets：具体是哪一期公告、哪个原始文件？
ingestion_runs：哪次处理把这个数字放进来？
observations：哪个周期，数值是多少，是否已核验？
```

`id` 是一条记录的唯一编号；`entity_id` 是引用实体编号的外键。外键让数据库阻止“客流引用了不存在的景区”这类错误。多张表通过编号关联，不在每条客流里重复复制景区全部信息。

## 2. 通用字段、类型与规则

目标环境为 MySQL 8.4、InnoDB、正文 `utf8mb4`。Python 与驱动版本在实现时选定并锁定。本文类型缩写：

| 写法 | 实际类型/含义 |
|---|---|
| `ID` | `CHAR(36)`，UUID，标识符列使用 ASCII 二进制排序规则 |
| `CODE` | `VARCHAR(48)`，ASCII 二进制排序规则，适用于固定代码 |
| `S(n)` | `VARCHAR(n)`；`TEXT` 是长文本 |
| `TS` / `DATE` | UTC `DATETIME(6)` / 日历日期，不混用 |
| `NUM` | `DECIMAL(20,4)`，Python 使用 Decimal，不经浮点数中转 |
| `HASH` | `CHAR(64)`，SHA-256 十六进制摘要 |
| `JSON` | 结构化元数据；输入由 DTO 校验，不用它替代常用查询列 |
| `?` | 可空；未标记的字段必填。可空默认 NULL，其余默认值须明确指定 |
| `→ table` | 外键引用该表主键；特殊目标列会明确写出 |

除另有说明，每个普通业务表附带 `id ID` 主键和 `created_at TS`。可修改主记录另有 `updated_at TS`、`row_version INT`（默认 1，每次修改加 1）；不可变原件、历史、计数、结果点没有 `updated_at/row_version`。关联表使用组合主键，不额外加 id；`metrics` 和 `sessions` 主键例外如下。

时间由应用显式赋值；空值不得伪装为当前时间。主键、外键不得默认为空字符串。外键默认 RESTRICT，不级联删除来源、观测和历史；首版通过停用/撤销保留业务历史，不提供批量物理删除功能。

用于复现的 JSON 快照中，Decimal 用十进制字符串编码、时间用带时区 ISO 字符串编码，并保留 snapshot_schema_version；读取后按 DTO 恢复类型。业务 HTTP 数值再由 D 按契约序列化。摘要基于固定字段顺序的规范化内容计算，不能依赖 Python 对象的字符串表示。

数据库负责外键、唯一键、非负数、起止顺序等行级约束；跨行时间窗不重叠、实体类型匹配、授权用途等由事务内的服务校验负责。CHECK 能力参照 [MySQL 官方说明](https://dev.mysql.com/doc/refman/8.4/en/create-table-check-constraints.html)。

## 3. 身份和基础目录

### `users`：D 的账户存储

字段：`username S(64)`、`display_name S(100)`、`password_hash S(255)`、`role CODE`、`status CODE`。

约束：username 唯一；由 D 统一用户名规范化规则后传入。role 为 viewer/admin；status 为 active/disabled。C 接收哈希，不接收明文密码。停用用户后，有效会话查询也必须失败。

### `sessions`：D 的服务端会话

主键改为 `id_hash HASH`，不含通用 id。字段：`user_id ID → users`、`expires_at TS`、`revoked_at TS?`。保留 created_at；不需要 row_version。

索引：`(user_id, expires_at)`、`expires_at`。有效会话要求未撤销、未到期且用户 active。CSRF token 的生成/验证由 D 实现；推荐由 D 根据会话及服务端秘密重新生成，不要求 C 存明文 token。如 D 采用其他机制，须在冻结前补充契约，C 不自行设计认证算法。

### `entities`：景区、车站、机场、摄像头

字段：`name S(200)`、`type CODE`、`region_code S(12)`、`longitude DECIMAL(10,7)?`、`latitude DECIMAL(10,7)?`、`parent_entity_id ID? → entities`、`status CODE`、`location_note TEXT?`。

type：scenic/rail_station/airport/camera；status：active/inactive。camera 必须关联 scenic 类型的 parent。经纬度为空时不在地图伪造位置；有值时校验合法范围。索引 `(type, region_code, status)`。名称不作为唯一标识，避免同名对象冲突。

### `metrics`：指标字典

主键为 `code CODE`，不含通用 id。字段：`display_name S(100)`、`definition TEXT`、`unit S(24)`、`supported_entity_types JSON`、`aggregation_rule CODE`、`comparability_note TEXT`、`dictionary_version S(32)`。

初始代码：scenic_visits、rail_departures、airport_throughput、camera_entries、camera_exits。首版标准单位为“人次”，视频展示必须注明估计通行次数，不暗示去重人数。聚合规则为同对象、同指标、同口径、互不重叠完整周期可相加；不能跨指标求“总客流”。视频分钟计数存在专表，不写入日/月观测表。

## 4. 来源、原件、批次和数据质量

### `sources`：持续来源登记

字段：`publisher S(200)`、`title S(300)`、`url TEXT`、`native_grain CODE?`、`usage_note TEXT`、`verification_status CODE`、`coverage_start DATE?`、`coverage_end DATE?`、`published_at TS?`、`retrieved_at TS?`、`update_frequency CODE`、`adapter_key S(64)`、`adapter_config JSON`、`enabled BOOLEAN`（默认 false）、`last_checked_at TS?`。

同一个 source_id 表示同一发布方、对象范围和统计口径的数据序列/资料来源；口径根本变化应登记新来源。每月新一期文章进入 source_assets，不随意更换整个序列的 source_id。native_grain 在资料/视频类来源可空，在数值来源必须明确。核验状态：verified/pending_review/rejected。

published_at/retrieved_at 是目录摘要的最近已核验发布时间/采集时间，不能代替每个数字自己的发布日期。adapter_config 只放来源地址和解析参数，不放密钥。启用采集须先登记使用条件。索引 `(enabled, last_checked_at)`。

### `source_assets`：不可变原件快照

字段：`source_id ID → sources`、`url TEXT`、`title S(300)`、`published_at TS?`、`retrieved_at TS`、`relative_path S(500)`、`sha256 HASH`、`media_type S(100)`、`byte_size BIGINT`、`usage_note TEXT`。

唯一键 `(source_id, sha256)`；byte_size 非负。相同字节不重复存原件，但每次检查仍有批次记录。文章内容变更保存新资产，旧文件不覆盖。没有准确发布时间保留 NULL 并注明未知；不能用采集时间冒充发布时间。

### `ingestion_runs`：一次来源处理

字段：`source_id ID → sources`、`job_id ID? → jobs`、`attempt_id ID? → job_attempts`、`asset_id ID? → source_assets`、`status CODE`、`dry_run BOOLEAN`、`reason TEXT`、`parser_version S(64)`、`normalizer_version S(64)`、`quality_rule_version S(64)`、`started_at TS`、`finished_at TS?`、`processed_count INT`、`imported_count INT`、`revised_count INT`、`skipped_count INT`、`quarantined_count INT`、`error_summary TEXT?`。

状态 running/succeeded/failed，计数默认 0 且非负。一次批次对应一个原件；一个来源返回多个原件则创建多个批次，同一个 job 汇总它们。网络检查无原件时允许 asset_id 为空。索引 `(source_id, started_at)`、job_id。

### `quality_issues`：问题与隔离记录

字段：`run_id ID → ingestion_runs`、`observation_id ID? → observations`、`row_locator S(300)?`、`code CODE`、`severity CODE`、`raw_payload JSON?`、`message TEXT`、`status CODE`、`resolved_at TS?`、`resolution_note TEXT?`。

severity：info/warning/error；status：open/resolved。格式不合法、缺来源等数据留在隔离记录，不强行制造观测；合法但存疑的观测可标 pending_review。索引 `(run_id, status)`。缺失周期可以生成报告，不需要为每个缺日永久写一条问题记录。

## 5. 客流观测与修订

### `observations`：当前可查的实际观测

| 字段 | 类型 | 含义 |
|---|---|---|
| entity_id | ID → entities | 统计对象 |
| metric_code | CODE → metrics.code | 统计指标 |
| period_start / period_end | DATE | 包含首尾日期的统计周期 |
| grain | CODE | day/week/month/holiday |
| value / unit | NUM / S(24) | 换算后的数值与单位 |
| original_value / original_unit | S(100) / S(24) | 原文中的数值及单位 |
| conversion_factor | DECIMAL(20,8) | 换算因子，默认 1 |
| source_id / asset_id | ID → sources / source_assets | 来源及具体原件 |
| ingestion_run_id | ID → ingestion_runs | 最后写入该版的批次 |
| source_locator | S(500) | 页码、表格、行或段落位置 |
| published_at / ingested_at | TS? / TS | 发布与入库时间 |
| quality_status | CODE | verified/pending_review/rejected |
| methodology_version | S(64) | 统计口径标识 |
| value_kind | CODE | 首版 observed；derived 仅在派生功能获准后使用 |
| derivation_manifest | JSON? | 派生所需输入版本与公式；普通观测为 NULL |

附带通用 id、created_at、updated_at、row_version。

唯一键：`(entity_id, metric_code, period_start, period_end, grain, source_id)`。

索引：`(entity_id, metric_code, grain, period_start)`、ingestion_run_id、asset_id。校验 value 非负、period_end≥period_start、单位与指标一致、原件/批次/source_id 一致。日、周、月必须符合周期边界。假期用准确起止日期匹配定义，不能由月份均分。

### `observation_revisions`：修订前的完整版本

字段：`observation_id ID → observations`、`version INT`、`snapshot JSON`、`superseded_by_run_id ID → ingestion_runs`、`change_reason TEXT`、`changed_at TS`。

唯一键 `(observation_id, version)`。修改前把当前记录全部写进 snapshot（含原件、批次、时间、单位、质量和口径），随后更新当前记录并递增 row_version，二者同事务。v1→v2 时历史保存 v1；查询某版本时，当前版本命中 observations，旧版本命中 revisions。审核质量变化也要留版本。

### `series_policies`：多来源选择

字段：`entity_id ID → entities`、`metric_code CODE → metrics.code`、`grain CODE`、`valid_from DATE`、`valid_until DATE`、`source_id ID → sources`、`reason TEXT`、`policy_version S(32)`。

索引 `(entity_id, metric_code, grain, valid_from, valid_until)`。同对象/指标/粒度的选源区间不得重叠；写入时锁定实体父记录后检查。一个查询周期必须由一条策略完整覆盖；不允许半个月选甲来源、半个月选乙来源。

若无策略且仅一个 verified 来源，可自动采用；若有多个来源，返回该期缺失并说明 source_conflict，不平均、不相加、不随意取最大值。`quality=all` 允许返回带来源标识的候选观测，D 不可当作单条可比较序列使用。

## 6. 假期与事件

### `holidays`

字段：`name S(200)`、`kind CODE`、`year SMALLINT`、`start_date DATE`、`end_date DATE`、`days_count SMALLINT`、`region_code S(12)`、`scope_key S(200)`、`definition_source_id ID → sources`、`definition_asset_id ID → source_assets`。

kind：may_day/national_day/summer/winter。scope_key 明确适用地区/学校。唯一键 `(kind, year, region_code, scope_key)`；同一年同校只有一个该类假期定义，修订通过受控更新并保留定义原件。days_count 与含首尾的日期长度一致。跨年寒假 year 按开始年记录，名称注明学年。

### `events`、`event_entities`、`event_history`

events 字段：`title S(120)`、`description TEXT`、`kind CODE`、`authority CODE`、`severity CODE`、`region_code S(12)`、`status CODE`、`starts_at TS`、`ends_at TS?`、`published_at TS?`、`last_verified_at TS?`、`source_id ID → sources`、`asset_id ID → source_assets`、`operator_note TEXT?`。

kind、severity 使用 HTTP 契约已有枚举；authority 为 official/model_signal；status 为 active/resolved。模型提示来源必须标成内部模型报告，不能挂官方名义；C 首版只整理官方公告。索引 `(region_code, status, starts_at)`。时间有效性由查询当次判断，不能只看 status；ends_at 为空不等于永久有效，D 需按公告核验策略控制当前展示。

event_entities：`event_id ID → events`、`entity_id ID → entities` 为组合主键，增加 `(entity_id, event_id)` 索引。

event_history 字段：`event_id ID → events`、`version INT`、`snapshot JSON`、`change_note TEXT`、`operator_user_id ID? → users`、`changed_at TS`。唯一键 `(event_id, version)`；创建写第 1 版，随后每次变更写变更后的完整快照。修改主记录、影响对象和历史同事务。

## 7. 知识资料和索引版本

### `knowledge_documents`

字段：`source_id ID → sources`、`asset_id ID → source_assets`、`title S(300)`、`publisher S(200)`、`source_url TEXT`、`published_at TS`、`valid_from TS?`、`valid_until TS?`、`permission_note TEXT`、`document_version S(64)`、`index_status CODE`、`active_index_version S(64)?`。

文件原件由 asset 定位；上传契约要求有 published_at，缺少时先在资料台账待核验，不冒充已可用文档。index_status 为 pending/processing/ready/failed，指最近构建状态；旧版可读性独立由 active_index_version 决定。

document_entities：`document_id ID → knowledge_documents`、`entity_id ID → entities` 组合主键。

### `knowledge_indexes`：一次索引版本

字段：`document_id ID → knowledge_documents`、`version S(64)`、`job_id ID → jobs`、`status CODE`、`artifact_path S(500)?`、`artifact_sha256 HASH?`、`chunk_count INT`、`parser_version S(64)`、`embedding_model_version S(100)`、`error_summary TEXT?`。

唯一键 `(document_id, version)`；status：building/ready/failed。E 管向量产物，C 保存指针/摘要和片段元数据。active_index_version 切换前必须验证同文档对应版本 ready 且产物可用。初次无索引时 active_index_version 为 NULL。

### `knowledge_chunks`

字段：`index_id ID → knowledge_indexes`、`chunk_no INT`、`text TEXT`、`locator JSON`、`text_sha256 HASH`。唯一键 `(index_id, chunk_no)`。

locator 明确 page/section/paragraph 等位置，至少一种有效定位；E 写入，D/E 读取引用。模型变更生成新索引版本，不覆盖旧片段，确保旧回答的引用仍能定位。

## 8. 录像、授权、分析和人工样本

### `permission_records`

字段：`source_id ID → sources`、`basis TEXT`、`grantor S(200)`、`evidence_path S(500)`、`evidence_sha256 HASH`、`allowed_uses JSON`、`valid_from TS`、`valid_until TS?`、`playback_allowed BOOLEAN`（默认 false）、`status CODE`。

status：pending/approved/revoked；allowed_uses 明确 analysis/replay 等用途。有效授权必须 status=approved、用途匹配且在有效期内；D 上传/回放时查询，worker 开始分析时复核。证明材料默认内部可见。

### `videos`

字段：`source_id ID → sources`、`asset_id ID → source_assets`、`scenic_id ID → entities`、`camera_id ID → entities`、`permission_record_id ID → permission_records`、`recorded_start_at TS`、`recorded_end_at TS`、`status CODE`、`camera_location_note TEXT?`。

status：uploaded/processing/ready/failed。校验所属景区与摄像头父实体一致、录制结束晚于开始、文件可访问、授权有效。索引 `(scenic_id, camera_id, recorded_start_at)`。若已有成功分析，新增分析失败不应使旧结果不可读；视频状态汇总优先 ready，再 processing，再 failed，尚无分析为 uploaded。

### `video_analyses`

字段：`video_id ID → videos`、`job_id ID → jobs`、`pipeline_version S(64)`、`detector_model_version S(100)`、`detector_sha256 HASH`、`openvino_version S(64)`、`device CODE`、`tracker_config_id S(100)?`、`tracker_config JSON`、`count_line JSON`、`entry_side CODE`、`interval_minutes SMALLINT`、`config_sha256 HASH`、`status CODE`、`manual_validation JSON?`。

唯一键 `(video_id, config_sha256)`；job_id 唯一。device CPU/GPU/NPU/AUTO，entry_side left/right，interval_minutes 为 1/5/15；count_line 的四个坐标在 0—1 且端点不重合，线起终点顺序固定，方向由 E 结合人工样本确认。status：queued/running/succeeded/failed。

manual_validation 由 E 提供，含 sample_count、entries_mae、exits_mae、汇总 mae、样本版本与评估时间。未知为 NULL，不填 0。

### `camera_counts`

字段：`analysis_id ID → video_analyses`、`window_start TS`、`window_end TS`、`entries INT`、`exits INT`、`quality_status CODE`。

唯一键 `(analysis_id, window_start, window_end)`，索引 `(analysis_id, window_start)`；计数非负、时间窗在录像范围内，按录像起点对齐且互不重叠。末尾不完整窗口不标 verified，不进入完整窗口预测输入。同窗同值重传跳过，同窗不同值返回冲突，不覆盖已完成结果。

### `manual_annotations`

字段：`video_id ID → videos`、`camera_id ID → entities`、`sample_key S(100)`、`version INT`、`window_start TS`、`window_end TS`、`entries INT`、`exits INT`、`annotator S(100)`、`direction_note TEXT`、`review_status CODE`。

唯一键 `(video_id, sample_key, version)`。review_status pending/verified/rejected；样本版本不可变，纠正后加版本。时间窗使用同一半开区间，记录视频偏移与录制时间的转换依据在 direction_note/样本说明中。

## 9. 历史与短时预测存储

### `forecast_runs`、`forecast_points`

forecast_runs 字段：`entity_id ID → entities`、`metric_code CODE → metrics.code`、`grain CODE`、`training_start DATE`、`training_end DATE`、`horizon SMALLINT`、`model_version S(100)`、`model_config JSON`、`input_manifest JSON`、`input_sha256 HASH`、`backtest JSON?`、`status CODE`、`reason TEXT?`。

grain week/month；status ready/data_insufficient；horizon 范围遵循 HTTP 契约。input_manifest 保存实际输入值、观测 id/version、来源、日期和质量、选源策略版本，不只保存会变化的当前记录 ID。对于初版小规模序列用 JSON 快照；超过契约大小限制才拆为外部不可变清单。backtest 保留 method/mae/smape/sample_count，无结果时允许 NULL。

forecast_points 字段：`run_id ID → forecast_runs`、`period_start DATE`、`period_end DATE`、`value NUM`、`lower_bound NUM`、`upper_bound NUM`。唯一键 `(run_id, period_start, period_end)`；非负且 lower_bound≤value≤upper_bound。不足状态没有 points；ready 要求点数与 horizon 一致。预测记录不可变，更换模型或输入重新建 run。

### `short_forecast_runs`、`short_forecast_points`

short_forecast_runs 字段：`analysis_id ID → video_analyses`、`cutoff_at TS`、`direction CODE`、`horizon_minutes SMALLINT`、`step_minutes SMALLINT`、`model_version S(100)`、`model_config JSON`、`input_manifest JSON`、`input_sha256 HASH`、`validation_error JSON?`、`status CODE`、`reason TEXT?`。

direction entries/exits；horizon_minutes 15/30/60；step_minutes 5/15；status ready/data_insufficient/quality_insufficient。输入清单只含 window_end≤cutoff_at 的计数及其 ID/摘要；不能使用越过截止时间的窗口。

short_forecast_points 字段：`run_id ID → short_forecast_runs`、`window_start TS`、`window_end TS`、`value NUM`、`lower_bound NUM?`、`upper_bound NUM?`。唯一键 `(run_id, window_start, window_end)`；ready 点数=horizon_minutes/step_minutes。上下界若提供必须成对且包住点值。

## 10. 作业与执行尝试

### `jobs`

字段：`type CODE`、`status CODE`、`idempotency_key HASH`、`payload JSON`、`payload_version S(32)`、`requested_by ID? → users`、`reason TEXT`、`attempt_count INT`（默认 0）、`available_at TS`、`started_at TS?`、`finished_at TS?`、`processed_count INT`、`imported_count INT`、`result_refs JSON?`、`error_summary TEXT?`。

唯一键 `(type, idempotency_key)`；领取索引 `(status, available_at, created_at)`。type ingestion/video_analysis/knowledge_index；status queued/running/succeeded/failed。payload 仅含可序列化参数与内部文件引用，不含函数对象或密钥。

### `job_attempts`

字段：`job_id ID → jobs`、`attempt_no INT`、`worker_id S(100)`、`lease_token ID`、`lease_expires_at TS`、`heartbeat_at TS`、`started_at TS`、`finished_at TS?`、`outcome CODE?`、`error_summary TEXT?`。

唯一键 `(job_id, attempt_no)`，lease_token 唯一。outcome succeeded/failed/expired，未结束时 NULL。结果写入事务必须核验当前 attempt_no 与 token、作业状态和租约；租约失效的旧进程不得再发布结果。
