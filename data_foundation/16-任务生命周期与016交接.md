## 新接口

```python
uow.jobs.update_progress(lease, processed_count, imported_count, now=None)
uow.jobs.retry_failed(job_id, reason, operator_id, now)
uow.knowledge.fail_index(index_id, error_summary, lease)

```

返回dict；list_videos返回items/page/page_size/total。get_job新增retry_history，含job_id、历史attempt_count、operator_id、reason、requested_at和记录ID，无租约token。get_video附analyses，普通详情/列表及授权读取不带本地录像路径或evidence_path。完整可调用签名见[实装清单](./09-接口实装核对与缺口清单.md)。

## 进度与管理员重试

进度是本次尝试的绝对计数；两个计数为非负整数且拒绝bool，imported_count≤processed_count，同一尝试不能倒退，相同计数可以重复写入。更新进度不续约；D继续单独调用heartbeat。now省略时在取得租约锁后使用实际UTC时间。到期前一微秒有效，恰好到期拒绝。

只有failed任务可retry_failed；操作者必须是users中的active admin，原因是非空、最多2000字符，now必须带时区。D仍须在HTTP层验证真实登录管理员，并从会话取得operator_id，不能信任浏览器传入的管理员ID。

重试按Job锁串行化，保留原payload、幂等键、reason、累计attempt_count、全部JobAttempt及失败业务记录；新增job_retries审计。清空本次开始/结束、计数、结果引用和错误；available_at=now。下一次claim才生成新租约和增加次数。重复或并发重试时，后到请求看到queued并抛Conflict，不创建第二条审计。

手动重试**不重置累计自动恢复上限**。例如已尝试3次的任务经管理员重试，会允许领取第4次，但第4次再到期时，默认max_attempts=3将直接failed，不再自动排队。管理员须确认重试原因，不能把接口接成无限自动重试。

```python
from datetime import datetime, timezone

with store.write() as uow:
    job = uow.jobs.retry_failed(job_id, "修复配置并核验半成品后重试", authenticated_admin_id,
                               datetime.now(timezone.utc))
# 提交成功后才向HTTP调用者返回重试成功。
```

## 失败、半成品与发布

索引begin/write/activate/fail和分析begin/write/complete/fail均校验lease与业务job_id，锁顺序为Job→JobAttempt→Document→Index，或Job→JobAttempt→Video→Analysis→Permission。持锁后刷新状态；不同任务即使有有效token，也不能修改他人的索引或分析。

fail_index保存错误，保留chunks和已有active_index_version；失败的新版本不会覆盖旧ready版本。相同任务、版本、parser_version和embedding_model_version可重新begin_index，清空错误并继续相同片段。配置改变必须新索引版本；不同任务不能接管已存在版本。ready版本不能再次构建、失败或追加。

fail_analysis保存error_summary及failed状态，保留计数；失败分析不能作为ready查询。管理员/自动恢复后，新lease先begin_analysis，再复用相同analysis。相同窗口、值及质量状态跳过；不同值或重叠窗口Conflict，算法/配置改变不能往旧记录追加。一个新分析失败不会使同录像的已有成功分析消失。相同录像/config_sha256已被其他job占用时create_analysis抛Conflict，不隐式复用他人的job。

业务fail方法**不自动结束Job**：D/E在同一write事务中调用业务fail和jobs.fail_job。发布同样在同一事务完成业务ready和jobs.complete_job。长解析、embedding、推理不持有事务。

```python
with store.write() as uow:
    uow.knowledge.fail_index(index_id, error_summary, lease)
    uow.jobs.fail_job(lease, error_summary, datetime.now(timezone.utc))

with store.write() as uow:
    uow.video.begin_analysis(analysis_id, new_lease)  # 重新验证analysis授权
# 在事务外推理，按批次用短事务write_counts及update_progress。
with store.write() as uow:
    uow.video.complete_analysis(analysis_id, expected_window_count, new_lease, manual_validation)
    uow.jobs.complete_job(new_lease, {"analysis_id": analysis_id}, datetime.now(timezone.utc))
```

这些保障覆盖C存储接口的确定性复用；E实际解析/算法处理函数、外部向量产物及D正式Worker的重试幂等还需要接收方验收。

## MySQL快照修复

独立竞争测试发现，MySQL REPEATABLE READ下取得Job锁后再次普通get可能重新读取旧快照。0.1.6进度/完成/失败继续以locking current read刷新Job；片段查重、计数重叠、发布数量及分析配置复用同样使用锁定当前读，避免缓存或旧快照造成倒退进度、重复写入、错计片段和重叠窗口。文档/录像业务锁还串行化不同任务对同一个对象的发布。队列扫描锁范围及高并发吞吐限制仍保留。

## 授权与回放

begin_analysis、write_counts、complete_analysis均重新检查当前approved、analysis用途及有效期；授权到期边界包含相等。失去授权仍可用有效lease记录业务失败，停止推理。get_playback_ref每次请求核验replay用途、playback_allowed和有效期，然后检查DATA_ROOT范围、文件存在、sha256与byte_size。拒绝绝对路径、路径穿越和指向目录外的符号链接。

get_playback_ref返回的path仅用于D内部文件响应，不能JSON原样返回浏览器。D在每次回放请求验证登录与访问权限，并使用受控流式响应/Range接口；本版未实现HTTP回放。返回引用的检查与之后打开/发送文件不是同一原子操作，D须避免文件被替换、权限变更后的长期缓存访问。大录像逐次摘要核验有IO成本，未验收大文件吞吐。
