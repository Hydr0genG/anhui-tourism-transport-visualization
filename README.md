# 安徽文旅交通客流观察与预测驾驶舱：项目文档

> 状态：架构与接口设计稿，尚未创建前后端代码。更新日期：2026-10-08。

## 项目介绍

本项目以安徽省景区、主要火车站和机场的客流数据为对象，建设简洁的 Web 数据可视化驾驶舱。系统重点展示客流分布、周/月变化、历史趋势预测和节假日对比，并结合突发事件与预警信息辅助观察客流变化。智能体提供带来源的问答分析；录制视频的人数统计用于演示景区入口短时客流预测。

## 当前确定的范围

- Web 应用：Vue 3 + TypeScript 前端，Python + FastAPI 后端。
- 用户输入用户名和密码登录后，才能查看驾驶舱及调用受保护的数据接口。首版不提供公开注册。
- 首批选择 1—2 个景区，以及与主题相关的主要火车站、机场；以数据可获得性确定最终名单。
- 定时任务每周检查来源并更新数据。来源只有月度数据时，保留月度粒度，不生成虚假的周数据。
- 展示历史周/月趋势及经过回测的预测；节假日专题和官方事件公告独立标注来源与口径。
- 视频模块先处理获准使用的录制视频，展示录像回放、入口进出计数和短时预测；不得称为真实实时数据或全景区在园人数。
- 录像计数采用 YOLOv8 行人检测 + OpenVINO 推理 + 目标跟踪 + 虚拟线进出计数；OpenVINO 负责推理加速，短时客流预测由独立模型完成。
- 智能体使用数据库查询回答数值问题，使用 RAG 检索官方说明、规则和公告回答解释性问题，并展示引用。

## 共同约定

1. 每条客流数据记录对象、指标、时间起止、粒度、数值、单位、来源、发布时间和采集时间。
2. `景区接待人次`、`铁路发送人次`、`机场旅客吞吐量`、`轨道客运量`、`入口视频计数`是不同指标，不直接相加。
3. 数据缺失保持缺失状态；预测不足时返回 `data_insufficient`，不伪造曲线。
4. 事件中心区分`官方公告`与`模型提示`；模型提示不能冒充官方预警。
5. 录制视频仅用于获授权的验证场景。对外驾驶舱默认展示聚合计数，不公开原始视频。
6. 工作区的临时文件统一放在上级目录 `../tmp/`，适时清理；正式项目文件放在本目录。
7. 未来代码按五个功能目录划分：`web_dashboard/`、`web_interactions/`、`data_foundation/`、`api_platform/`、`intelligent_analysis/`。成员只在各自主责目录内开发，跨目录通过约定的导出接口集成；目录名不含成员字母。详见[文件树和归属规则](./04-项目架构与文件树.md)。

## 安全设计依据

密码采用自适应哈希而非明文保存；服务端会话通过安全 Cookie 传递，退出登录时使会话失效。实施时参照 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 和 [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。
